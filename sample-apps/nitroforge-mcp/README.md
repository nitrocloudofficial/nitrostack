# NitroForge

An MCP server that builds MCP servers. Point it at an OpenAPI spec; get back a
verified, deployable NitroStack MCP server — clustered tools, derived Zod
schemas, and a UI widget — with every stage observable over the MCP protocol.

Stack: **NitroStack CLI + SDK (TypeScript)** · Docs: https://docs.nitrostack.ai/
Full design + workstream detail: `docs/README-team.md`, `docs/WORKFLOW.md`,
`docs/BUILD-W1.md`, `docs/BUILD-W2.md`. **Picking up W2 or W3 cold? Read
`docs/HANDOFF-W2.md` or `docs/HANDOFF-W3.md` first** — each has the exact
contract you need to implement, plus every gotcha already found so you don't
rediscover them.

## Setup

```bash
npm install
cp .env.example .env   # then fill in ANTHROPIC_API_KEY
npm run typecheck
npm test
```

> **`nitrostack-cli`** (global install) ships without a runnable `bin` in the
> public npm registry snapshot we hit — the documented CLI dev/build/generate
> commands aren't invokable as-is. This repo is hand-scaffolded to the exact
> structure NitroStack expects, and builds/typechecks/tests cleanly against
> the real `@nitrostack/core` + `zod` + `@apidevtools/swagger-parser`. If
> someone finds a working CLI path, flag it — `generate types` in particular
> would save W2/W3 real time on widget type sync.

> **Doc discrepancies (see `docs/README-team.md`)** — resolved by reading the
> real installed package (`node_modules/@nitrostack/core/dist/core/*.d.ts`)
> rather than a throwaway scaffold. Full verified answers are in `CLAUDE.md`.
> Headline one: `Tool`/`Resource`/`Prompt` bare-exported from `@nitrostack/core`
> are the *builder classes*, not the decorators — decorators are
> `ToolDecorator`/`ResourceDecorator`/`PromptDecorator`/`ControllerDecorator`.
> The Quick Start's aliased-import style is correct; the SDK Reference's plain
> `import { Tool }` example is stale.

### W1 — done

- `src/contracts/*` — frozen: `endpoint-graph.schema.ts`, `ir.schema.ts`,
  `generated-project.schema.ts`, `store.contract.ts`, `activity.contract.ts`,
  `ports.ts`. All typecheck against the real `@nitrostack/core`.
- `parser.service.ts` — OpenAPI → `EndpointGraph`. `$ref` resolution delegated
  to `@apidevtools/swagger-parser`'s `dereference()`; we own `allOf` flattening
  and refuse (never guess at) `oneOf`/`anyOf`. Throws `SpecParseError` rather
  than defaulting on anything unresolvable. 8/8 tests, snapshot-tested.
- `planner.service.ts` + `prompts/planner.prompt.ts` (versioned, v2) — the one
  LLM call. Model sees a **compacted** graph (id/method/path/summary/tags/
  param-names only, no schemas). Zod + graph-cross-reference validation +
  retry-with-feedback capped at 2. 6/6 tests, mocked model calls.
- `ingest.tools.ts` — the real MCP tool surface: `parse_spec` (`@Cache({ttl:3600})`)
  and `plan_tool_surface` (`@RateLimit`, `@Widget('tool-surface')`), both with
  `invocation` status strings and realistic `examples`. Thin wrappers over the
  services above, persisted via `ArtifactStore`. 3/3 integration tests.
- `src/testing/in-memory-artifact-store.ts` — temporary `ArtifactStore` stand-in
  so W1 isn't blocked on W3; swap the provider binding in `ingest.module.ts`
  once `store.service.ts` ships.
- `fixtures/specs/demo.yaml`, `fixtures/graphs/demo.graph.json` (generated by
  actually running the parser), `fixtures/irs/demo.ir.json` (hand-written,
  6 tools / 3 modules, validated against both Zod and the graph).

**17/17 tests passing.** `npm run build` / `npm run typecheck` clean.
