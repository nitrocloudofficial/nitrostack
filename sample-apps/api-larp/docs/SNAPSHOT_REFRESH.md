# Snapshot refresh procedure

The judged path uses a committed, provenance-tagged repository snapshot. The snapshot is generated by the same `GitHubEvidenceProvider` used by live mode.

## Configure

```bash
cp .env.example .env
```

Set:

```dotenv
GITHUB_TOKEN=<fine-grained read-only token>
DEMO_GITHUB_OWNER=<public demo organisation>
DEMO_GITHUB_REPOSITORIES=react-consumer,python-consumer,go-consumer
DEMO_SCENARIO=risky
```

## Refresh

```bash
npm run snapshot:refresh
```

The command:

1. Loads the baseline and candidate OpenAPI files.
2. Runs the deterministic diff engine.
3. Generates change-linked search queries.
4. Calls the live GitHub adapter.
5. Fetches source at exact commit SHAs.
6. Extracts bounded snippets and line ranges.
7. Computes SHA-256 content hashes.
8. Validates the output with Zod.
9. Replaces `fixtures/scenarios/risky/evidence.snapshot.json`.

## Verify

```bash
USE_LIVE_GITHUB=false USE_LLM=false npm run dev
```

Run `refresh_repository_evidence` and `run_impact_assessment` in NitroStudio. Confirm that the source mode is `snapshot`, hashes validate, and repository commit SHAs are visible.
