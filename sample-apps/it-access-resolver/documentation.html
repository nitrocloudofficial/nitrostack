🛡️ IT Access Resolver

Autonomous Enterprise MCP Server, SOC-2 Compliance Audit Engine & L1 Self-Service Portal

🎯 The Problem Statement

In modern corporate networks, IT support helpdesks are overwhelmed by Level-1 trouble tickets whenever employees suddenly lose access to essential tools like Figma, Slack, or secure Shared Drives. Traditional remediation is expensive and tedious because the root causes are trapped across disparate system consoles:

👥 Active Directory & SSO

An employee has an active account, but their identity record lacks the mandatory directory security group (e.g., design-all) required for tool Single Sign-On.

🔑 Software License Exhaustion

The application pool has reached its hard licensing quota (e.g., 20/20 seats in use), blocking automated provisioning even when group memberships are correct.

💸 Wasted IT License Budget

Suspended, departed, or unactivated pending users continue consuming expensive, premium SaaS license seats without an automated auditing engine to reclaim them.

📡 Network & Zero-Trust Failures

Access is blocked because an employee attempted login from an untrusted personal endpoint or experienced an expired VPN authentication handshake.

🛠️ What All Was Implemented

1️⃣ Core Diagnostic & Remediation Backend (AccessModule)

  • Simulated Datastore: Pre-loaded fixtures for active/suspended identities (identities.json), license pools (licenses.json), VPN states (network.json), and support queues (tickets.json).
  • Atomic Diagnostic Tools: Exposes functions to check identities (check_identity_status), directory group memberships (check_group_membership), software seat availability (check_license_availability), and VPN trust tokens (check_network_status).
  • Algorithmic Synthesizer (diagnose_root_cause): Synthesizes data across all 4 checks to pinpoint the exact failure point (not_in_group, no_license, network_issue, or account_suspended).
  • Automated Remediation Actions: Tools that grant/revoke group memberships (add_to_group, remove_from_group), expand software seat pools (request_license), and reset network VPN tunnels (reset_network_access).

2️⃣ Intelligent Ticket Orchestration Engine (TicketTools)

  • Lifecycle Ticket Management: Guides issues through a formalized state machine: open ➔ diagnosing ➔ resolved / escalated.
  • ticket_run_full_diagnosis: Evaluates all identity security checkpoints in one atomic operation and attaches a granular diagnostic scorecard to the ticket for UI steppers.
  • ticket_apply_fix: Autonomously executes self-healing functions based on the diagnosed root cause. If an issue requires human HR review (such as a pending unactivated onboarding account), the system automatically escalates it with reasoning.

3️⃣ Enterprise Governance & API Protection (Phase 3)

Why Governance? To protect internal AD identity providers and prevent automated loop bugs from purchasing unnecessary software license seats!

  • Throttling (@RateLimit): Limits ticket_create_ticket to 10 req/min and ticket_apply_fix to 5 req/min. Spamming requests beyond this threshold triggers native interceptor rejection.
  • High-Performance Caching (@Cache): Applies a 15-second TTL cache to dashboard data fetching (ticket_get_all_tickets), eliminating redundant database overhead during interactive frontend polling.

4️⃣ SOC-2 Style Compliance Audit Engine (AuditModule — Phase 2)

  • Event-Driven Decoupling: Tool executions asynchronously dispatch lifecycle domain events (emitEvent('ticket.created'), ticket.diagnosed, ticket.resolved, and ticket.escalated).
  • Immutable Compliance Ledger (AuditService): Subscribes via @OnEvent to generate sequential audit records (AUD-001, AUD-002) recording timestamps, automated flags, root causes, and corrective descriptions.
  • Simulated Employee Notifications: Formats realistic Slack/Email alert confirmation messages (e.g., "✅ Hi E103, your access issue (TKT-005) has been resolved. Added employee E103 to group 'design-all'.").
  • ReadOnly MCP Resources (AuditResources): Exposes inspection feeds via standard MCP Resource URIs: audit://history (entire immutable log), audit://recent (latest 10 entries), and tickets://all.

5️⃣ Standard Operating Procedure Prompts (AccessPrompts — Phase 1)

Pre-packaged operational instructions in NitroStack Studio's Prompts tab guiding AI assistants through complex multi-step workflows without requiring manual prompt engineering:

  • access_triage_open_tickets: Autonomous backlog clearance loop. Commands the AI to ingest all tickets, isolate open items, run full diagnostic steppers sequentially, output an executive Markdown synthesis table, and call automated remediation tools on all fixable cases!
  • access_onboard_employee_access: Parameterized onboarding routine accepting an employeeId and toolsNeeded (e.g., "Slack,Figma"), systematically verifying identity status, testing device VPN trust, and provisioning directory memberships.
  • access_audit_license_usage: Financial license auditing scan. Cross-references identity feeds against license quotas to highlight inactive/suspended accounts consuming paid software seats, computing reclamation savings.

6️⃣ Interactive Micro-Frontend Widgets (Phase 4)

Built with Next.js and @nitrostack/widgets, transforming raw terminal JSON outputs into rich visual dashboards inside NitroStack Studio:

  • IT Ticket Dashboard (/ticket-dashboard): Visual ticketing board organized into interactive filter tabs (All, Open, Diagnosing, Resolved, Escalated). Features expandable detail cards showing root cause icon badges and smart action buttons (Diagnose, Apply Fix, Escalate) that dispatch instructions to the AI chat via sendFollowUpMessage().
  • Zero-Credit In-Widget Ticket Creation Modal 🟢: Features a ＋ New Ticket modal form directly inside the UI. Utilizes the React hook callTool('ticket_create_ticket') to communicate directly with the server—creating real support tickets, logging compliance audit events, and updating the visual queue instantaneously without spending $0 in AI tokens or Compose credits!
  • Diagnostic Stepper (/ticket-diagnosis): Visual pass/fail scorecard displaying the precise status of Identity, AD Group, License Seat, and Network Security checks during diagnostic operations.
  • Fullscreen & Inline Display Mode Toggling: Embedded UI controls using requestFullscreen() and requestInline() for expanded screen real estate during incident triage.
